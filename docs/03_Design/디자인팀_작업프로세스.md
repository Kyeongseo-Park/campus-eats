# 디자인팀 작업 프로세스 — "학식 말고 뭐 먹지?"

---

## 1. 전체 작업 흐름

```
1. 아래 "현재 디자인 스펙" + 미리보기 파일(실제_디자인스펙_미리보기.html)로
   지금 실제 사이트 상태 확인
        ↓
2. "색상/폰트 말고 또 뭘 정해야 하지?" 본인 AI에게 먼저 질문
   (아래 2번 체크리스트 참고)
        ↓
3. 항목별로 레퍼런스(다른 앱 화면)를 찾아서 AI에게 "이런 방향 어때?" 검토 요청
        ↓
4. 결정 사항을 반영한 목업 만들기
   (반드시 실제 화면 스크린샷을 먼저 AI에게 보여주고, 그 위에 변형하는 방식으로 —
   백지에서 새로 그리게 하면 실제 구조와 어긋나기 쉬움)
        ↓
5. 팀장에게 컨펌 요청 (아래 5번 기준으로 판단)
        ↓
6. 진행 중 개발팀만 아는 정보가 필요하면
   → 먼저 본인 AI에게 물어보고 → 그래도 모르겠으면 그때 개발팀에 구체적으로 요청
```

---

## 2. 색상/폰트 외에 추가로 결정해야 할 것 (체크리스트)

이미 정해진 색상·폰트·모서리 값 외에, 아래 항목들도 결정이 필요합니다. 본인 AI에게 "이런 걸 어떤 기준으로 정하면 좋을지, 다른 앱은 어떻게 하는지" 물어보면서 하나씩 정해보세요.

- **여백의 리듬**: 요소들 사이 간격 규칙 (촘촘하게 vs 넉넉하게)
- **아이콘 스타일**: 통일된 아이콘 세트 사용 여부 (예: 전부 선(line) 스타일 vs 채움(filled) 스타일)
- **빈 화면/에러 화면**: "리뷰가 아직 없어요" 같은 빈 상태를 텍스트만 보여줄지, 일러스트를 곁들일지
- **이미지 톤**: 식당 사진이 있을 때/없을 때 플레이스홀더 처리 방식
- **인터랙션 디테일**: 버튼 눌렀을 때 효과, 로딩 중 표시 방식 등
- **정보 밀도**: 카드 하나에 정보를 얼마나 많이/적게 보여줄지
- **톤앤매너 문구**: 에러 메시지·안내 문구의 말투 (예: "쩝쩝박사님" 같은 캐릭터 톤을 다른 곳에도 확장할지)

---

## 3. 목업 만들 때 지켜야 할 것

- **새로운 화면을 처음부터 새로 그리지 않습니다.** 반드시 실제 배포된 사이트 화면(스크린샷 또는 아래 미리보기 파일)을 먼저 AI에게 보여주고, "이 구조는 그대로 두고 여기에 이런 요소만 추가/변경한 모습을 보여줘"라고 요청합니다.
- 색상은 아래 "현재 디자인 스펙"의 팔레트 안에서만 사용합니다. 새로운 색이 꼭 필요하면 팀장에게 먼저 확인합니다.

---

## 4. 개발팀에 정보 요청이 필요할 때

1. 먼저 본인 AI에게 "이 정보를 알아낼 방법이 있는지" 물어봅니다.
2. AI도 답을 못 주는 경우에만, 개발팀에 **구체적으로 무엇이 필요한지** 명시해서 요청합니다.
   - 나쁜 예: "정보 좀 주세요"
   - 좋은 예: "리뷰 작성 화면에서 별점 선택 시 최대 글자수 제한이 있는지 알려주세요"

---

## 5. 컨펌 기준 (팀장이 이 3가지로 판단)

- [ ] 색상이 기존 팔레트(오렌지 계열)와 어울리는가, 완전히 동떨어진 색인가
- [ ] 지금 실제 배포된 화면과 레이아웃 구조가 비슷한가 (완전히 다른 구조면 반려)
- [ ] 이 화면만 유독 튀어 보이는가 (다른 화면들과 나란히 놓고 봤을 때)

## 6. 현재 디자인 스펙 (실제 코드 기준 — 이론이 아니라 검증된 값)

> 별도 파일 `실제_디자인스펙_미리보기.html`을 열어서 시각적으로도 확인 가능합니다.

| 토큰 | 값 | 비고 |
|---|---|---|
| radius-sm | 6px | |
| radius-md | 8px | 카드/버튼 기본, 압도적 다수 사용 |
| radius-lg | 10px | 기본값(base) |
| radius-xl | 14px | |
| radius-2xl | 18px | 지도 박스 |
| radius-3xl | 22px | |

### 색상

| 토큰 | 값 | 용도 |
|---|---|---|
| primary | orange-500(라이트) / orange-400(다크) | 포인트 컬러 |
| secondary | orange-50(라이트) / orange-500 18%opacity(다크) | 보조 배경 |
| destructive | 빨강 계열 | 에러/경고 |
| border / input | 중성 회색 | 테두리 |

> **예외**: 지도 마커 색상만 하드코딩 (일반 `#FF6B00`, 선택됨 `#EF4444`) — 카카오맵 API 특성상 CSS 변수 미적용

### 폰트 크기

| 클래스 | 값 | 용도 |
|---|---|---|
| text-xs | 12px | 캡션, 보조설명 |
| text-sm | 14px | 본문, 대부분의 텍스트 |
| text-base | 16px | Input 기본, 카드 제목 |
| text-lg | 18px | 헤더 타이틀, 섹션 소제목 |
| text-xl | 20px | |
| text-2xl | 24px | 페이지 제목 (거의 전부 이 값) |

### 공통 UI 요소

| 컴포넌트 | Radius | 텍스트 | 비고 |
|---|---|---|---|
| Button (default) | 8px | 14px | |
| Button sm | 8px | 12.8px | |

### 화면별 주요 값

**헤더 (공통)**
- 여백: px-4 py-2 (16px/8px)
- 로고 배지: 28px, radius 10px
- 타이틀: 18px bold
- nav 링크: 14px medium

**홈 (지도+바텀시트)**
- 지도 박스: radius 18px, padding 12px
- 필터 칩: 완전 둥근형(pill), 12px 텍스트
- 바텀시트: 상단만 radius 8px, 핸들 6×40px
- 리스트 카드: radius 8px
- 내 위치 버튼: 44×44px 원형
- 별점 아이콘: 14px

**식당 상세**
- 페이지 여백: padding 32px, gap 24px
- 식당명: 24px
- 전화번호: 14px (회색)
- 제휴이벤트 소제목: 18px medium
- 리뷰 카드/작성폼: radius 8px, padding 12px

**로그인/회원가입**
- 카드 폭: 384px (max-w-sm)
- 제목: 24px
- 필드 간격: 16px (라벨-인풋 간격 6px)
- 에러 텍스트: 14px, destructive 색상
- 보조설명: 12px

**마이페이지 / 식당 제보 / 관리자 화면**
- 공통적으로 카드 radius 8px, 페이지 제목 24px, 본문 14px, 캡션 12px 패턴을 따름
- 관리자 테이블: 셀 padding 12px, 헤더 배경 muted 50%, 상태 뱃지 radius 26px

### 전체 공통 패턴 요약

- 페이지 여백은 거의 전부 32px + gap 24px
- 페이지 제목은 거의 전부 24px bold
- 카드/리스트 radius는 8px가 압도적 다수
- 본문 14px, 캡션 12px 패턴이 전체에 일관 적용
- 버튼은 shadcn 기본 스타일 그대로, 필터 칩류만 완전 둥근형(pill) 예외
- primary 색상(오렌지 계열)이 전체에 일관 사용
