네이티브 앱(Capacitor) 로그인 — 현황과 남은 작업

기존 웹앱을 Capacitor로 감싸 iOS/Android 네이티브 앱으로 출시하는 작업 중, "카카오/구글
소셜로그인이 앱 안에서도 동작하게 만드는" 부분의 인계 문서입니다. (기존 개인 작업노트
NativeApp_Capacitor.md 는 git 추적에서 제외되어 클론에 포함되지 않습니다.)

배경: 앱은 정적 빌드가 아니라 배포된 Next.js 사이트(https://campus-eats-lime.vercel.app)를
웹뷰로 그대로 불러오는 구조입니다. 그런데 구글은 임베디드 웹뷰의 OAuth 요청을 정책으로
차단하고, 카카오도 웹뷰에서 세션 유지가 불안정합니다. 그래서 "로그인 버튼을 눌렀을
때만" 앱 내장 웹뷰가 아니라 시스템 브라우저(iOS SFSafariViewController / Android Chrome
Custom Tabs)를 열어 OAuth를 끝내고, 커스텀 URL 스킴(campuseats://)으로 앱에 복귀시킵니다.

1. 이미 구현되어 main에 병합된 부분 (코드 작업 없음)
================================================================

로그인 흐름 (커밋 0c04b16, 2819674):
  웹뷰에서 로그인 클릭
   → src/components/social-login-buttons.tsx: Capacitor.isNativePlatform() 분기,
     @capacitor/browser 로 시스템 브라우저 열기
   → 시스템 브라우저에서 카카오/구글 OAuth 완료 (세션 쿠키 발급됨)
   → src/app/mobile-auth-bridge/page.tsx: 일회용 교환코드 생성
     (JWT, 세션 쿠키와 다른 salt, 60초 만료, 서버 인스턴스 내 재사용 방지)
   → src/components/auto-redirect.tsx: campuseats://auth-callback?code=... 딥링크로 앱 복귀
   → src/components/capacitor-auth-bridge.tsx (RootLayout에 전역 마운트):
     App.addListener("appUrlOpen") 로 딥링크 수신 → signIn("mobile-exchange", { code })
   → src/lib/next-auth.ts 의 mobile-exchange Credentials 프로바이더가 코드 검증
     → 웹뷰 쪽에도 세션 쿠키 이식

네이티브 딥링크 설정:
  - Android: android/app/src/main/AndroidManifest.xml 에 intent-filter
    (scheme="campuseats", host="auth-callback"), launchMode="singleTask"
  - iOS: ios/App/App/Info.plist 의 CFBundleURLSchemes 에 "campuseats"

프로바이더 설정 (src/lib/next-auth.ts):
  - 카카오: 개인정보 동의항목 전부 미사용, profile.id(회원번호)만 사용
  - 구글: scope "openid" 만 요청, profile.sub 만 사용
  - 환경변수: AUTH_KAKAO_ID, AUTH_KAKAO_SECRET, AUTH_GOOGLE_ID, AUTH_GOOGLE_SECRET
  - 세션 전략: jwt

최근 수정 (커밋 70005c6, hg-branch, 2026-09-08 — 아직 push 안 됨):
  - 로그인 후 앱 복귀 시 Browser.close() 호출 추가.
    iOS SFSafariViewController 는 딥링크만으로 자동으로 닫히지 않아 사파리 뷰가
    화면에 남는 문제가 있었음. Android/웹에서는 no-op이거나 무해.

2. 남은 작업 (코드가 아니라 설정 + 실기기 검증)
================================================================

(1) OAuth Redirect URI 등록 확인  ── 담당: 인증/배포 담당자
    카카오 디벨로퍼스, Google Cloud Console 양쪽에 아래 URI가 등록돼 있어야 함:
      https://campus-eats-lime.vercel.app/api/auth/callback/kakao
      https://campus-eats-lime.vercel.app/api/auth/callback/google
    정식 도메인(campus-eats.co.kr) 연결 시 그 도메인 URI도 추가 등록 필요.

(2) 환경변수  ── 담당: 팀장
    - Vercel(배포): AUTH_SECRET, AUTH_KAKAO_ID/SECRET, AUTH_GOOGLE_ID/SECRET
      이미 배포가 돌아가고 있으면 세팅된 상태.
    - 로컬: 클론엔 .env.example 만 있음. 로컬에서 로그인 테스트하려면
      .env 를 만들고 팀 공유 값으로 채워야 함 (DevSetup.md 3번 참고).

(3) Android 실기기/에뮬레이터 테스트  ── 담당: Android 테스트 담당
      npx cap sync android
      npx cap open android      # Android Studio 에서 빌드 → 실행
    확인 항목:
      - 로그인 화면에서 "카카오로 시작하기" → 시스템 브라우저(Custom Tabs) 열림
      - 카카오 로그인 완료 → 앱으로 자동 복귀 → 로그인 상태 유지
      - 구글도 동일하게 확인 (구글은 웹뷰였다면 여기서 실패했을 것)
      - 로그인 후 Custom Tab 이 닫히거나 앱이 앞으로 나옴
      - 앱 재실행 시 로그인 유지, 로그아웃 정상

(4) iOS 실기기 테스트  ── 담당: iOS 테스트 담당 / PM
    선행 조건: Apple Developer 계정이 승인 완료돼야 실기기 코드 서명 가능.
      → PM 에게 계정 상태 먼저 확인.
    ★ 주의: iOS 용 cap sync 는 반드시 macOS 에서 실행할 것.
      Windows 에서 npx cap sync 를 돌리면 ios/App/CapApp-SPM/Package.swift 의
      플러그인 경로가 역슬래시(\)로 생성되어 Mac 빌드가 깨진다.
    ★ 현재 git 에 커밋된 ios/App/CapApp-SPM/Package.swift 에는
      @capacitor/app / @capacitor/browser 플러그인 의존성이 빠져 있다.
      (커밋 0c04b16 이후 갱신 안 됨 → iOS 는 아직 이 플러그인으로 빌드된 적 없을 가능성)
      Mac 에서 아래를 실행하고, 정상 생성된 Package.swift 를 커밋해야 한다:
        npm ci
        npx cap sync ios
        npx cap open ios        # Xcode 에서 Signing & Capabilities > Team 지정
    확인 항목:
      - "구글로 시작하기" → SFSafariViewController 열림 → 로그인 → 앱 복귀
      - ★ 로그인 완료 후 사파리 뷰가 자동으로 닫힘 (커밋 70005c6 의 목적)
      - 카카오도 동일 확인, 로그인 유지 / 로그아웃 정상
